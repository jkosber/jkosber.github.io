Computing Logic was a programming foundations class: planning a program in pseudocode, flowcharts and UML before writing it, then writing small Python programs in IDLE. It ran as an eight-week late-start section.

Result. Seven modules of program design and Python: modular pseudocode with hierarchy charts and flowcharts, a UML use-case diagram, loop and decision scripts with their IDLE output, and a team pay-calculator script.

What the course provided and what I did

The course provided the assignment prompts and scenarios, the Excel templates for Modules 1 and 3, Lucidchart for the diagrams, and the team project brief. My part:

  • Wrote the pseudocode and drew the flowcharts, hierarchy charts and UML diagram
  • Filled in the number-system, memory and logic-gate workbooks
  • Wrote the Python for Modules 6 and 7 and the in-class practice scripts
  • Led a five-person team project, responsible for employee data management and for security and compliance

Strongest work

Breaking a program into modules (Module 2)

The scenario was a cleaning service that charges a base fee plus a rate per bathroom and per other room. I drew a hierarchy chart, then wrote the pseudocode as three modules: housekeeping asks for a customer's last name, the detail loop takes the room counts and shows the charge, and end-of-job closes the program. The rates are named constants, and typing ZZZZ as the name ends the loop:

Constants:
  BATHROOM_CHARGE = 15
  OTHER_ROOM_CHARGE = 10
  BASE_CHARGE = 40

Call Housekeeping Module

While lastName != "ZZZZ"
    Call Detail Loop Module
End While

Call End-of-Job Module

The flowchart matches it, with module-call symbols and a Yes/No loop on the sentinel. I did the second exercise, a contractor's job estimate, the same way: an HOURLY_RATE constant, materials marked up 20 percent from wholesale, and 0 hours to stop.

Planning a quiz game (Module 5)

I wrote the rules first: each question can be answered only once, a right answer adds points, a wrong one leaves the score alone, and the game has to handle invalid input. Then I turned the rules into steps and the steps into a flowchart. It loops while questions are left, sends an invalid choice back to the prompt, and branches on the answer before marking the question as answered.

One step didn't make it from the plan into the chart: the plan ends by announcing a winner, and the chart only shows the final score.

The team pay calculator

Our five-person team built a payroll script in Python. I was team leader, responsible for employee data management and for security and compliance. The file doesn't mark who wrote which section, so this describes the team's code:

  • Employee data: a table of ten employee IDs and hourly rates, and a loop that asks for an ID until it matches one
  • Time tracking: a loop that rejects hours outside 0 to 80
  • Payroll: 40 regular hours, overtime at 1.5 times the rate, flat 5.6 percent state and 7.9 percent federal tax, and net pay
  • Export: collects ten employees and writes them to Payroll.xlsx with pandas

What I'd fix: typing a word for hours crashes it, because float() runs before the range check; the number of dependents is collected but never used; and the security side of my role doesn't show up in the code, which has no login and overwrites the spreadsheet without asking.

Limits

  • Most of this class is design work: pseudocode and diagrams that never ran. The only run output is the two IDLE screenshots for Modules 6 and 7.
  • The pay calculator is the team's file, and the repository has no final project write-up. I haven't run it for this page; it needs pandas and an Excel writer.
  • Debugging exercises 2 to 4 are the program listings only, without my changes.
  • A few answers have mistakes: two spaces coded as "NULL" instead of 32 in the ASCII sheet, a NAND truth table filled in with NOR's values, and a UML diagram that draws Log In and Process Payment as extensions of Checkout where include fits better.
  • The Module 6 flowchart is a Lucidchart link, not a file in the repository.
