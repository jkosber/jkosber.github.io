Linux and Virtualization Technologies covered running Linux in VirtualBox and on AWS, managing it from the command line and scripting it in Bash. The course project was a two-server deployment of the AdventureWorks sample app, built in milestones across the term.

What the course provided and what I did

The course provided the worksheets and their questions, an AWS Academy lab account, the install commands for each project milestone, the application and database archives, and the requirements for each script, including a few one-line hints. My part:

  • Built Linux Mint and Fedora VMs in VirtualBox and did the Linux labs on them and on the AWS servers
  • Launched the two EC2 servers, ran the database and web installs, imported the data and tested the app
  • Wrote the input-checked scripts and the wallpaper downloader in Bash and ran each one
  • Answered the worksheet questions in my own words and wrote the final project report

Strongest work

AdventureWorks on two AWS servers

I ran the course's two-tier design on two Ubuntu EC2 instances: SQL Server on one, Apache and PHP on the other. The finished app returned 304 products on a blank search, opened product pages and saved a review with my name. My report lists the four problems I hit and how I fixed them. The first was "Connection Timed Out: The web server could not talk to the database," which I fixed by adding a security-group rule for port 1433 from the web server.

The full write-up is on AdventureWorks on AWS.

Rejecting bad input in a Bash game (M05P2B)

The course provided a number-guessing game that crashed on text or an empty answer, plus a one-line test for "is this an integer." I wrapped the game in that check, then wrote ex4.sh to take the range from two arguments. It has three checks before the game starts, each with its own message and exit 1:

  • Both arguments present
  • Both arguments whole numbers, tested with [[ "$min_arg" =~ ^[0-9]+$ ]]
  • The maximum greater than the minimum

The worksheet listed seven runs to try. This is my run of all seven, from the screenshot in my write-up, with the prompt shortened:

$ ./ex4.sh 1 50
Guess a number between 1 and 50: 45
My number is 14. You guessed 45.
Sorry, better luck next time!
$ ./ex4.sh 50 40
The second number (40) must be greater than the first (50).
$ ./ex4.sh 20 20
The second number (20) must be greater than the first (20).
$ ./ex4.sh 10
Incorrect input detected!!
Please provide a minimum and maximum number
Example: 1 10
$ ./ex4.sh zzz 10
Both arguments must be integers.
$ ./ex4.sh 10 zzz
Both arguments must be integers.
$ ./ex4.sh
Incorrect input detected!!
Please provide a minimum and maximum number
Example: 1 10

The checks quote their variables, but none of the four scripts uses set -euo pipefail, and the two that read input don't use read -r.

A wallpaper script that checks before it acts (M06P1A)

The assignment asked for a script that takes an image URL and a new name, then downloads the image, scans it for viruses, converts it to JPEG and renames it with its resolution. The course gave hints for the hardest pieces: the URL-to-filename pipeline, the curl status check, the clamscan call and the resolution regex. I put them together into dl_wallpaper.sh, with every check before any real work:

Check How the script handles it
Wrong number of arguments Prints usage to stderr and exits 1
URL can't be reached Prints an error to stderr and exits 1
Any status other than 200 Prints the status to stderr and exits 1, so redirects are rejected too
Infected download Deletes the file and exits 1 before converting it
Not already a JPEG Converts it with ImageMagick

My run shows the usage message with no arguments, then each progress step and a finished poptart_2560x1440.jpg from the course's sample image. What I'd change: $1, $filename and $newname are unquoted throughout, and the filename comes straight from the URL into an unquoted rm, so a URL ending in * could make it delete other files in the folder.
